# Module 4A project: andreiul.com

Andrei Pirvu, Cybersecurity master's programme.

## Scope

This repository carries two systems:

1. **The live website** www.andreiul.com: a static site on my own VPS behind nginx. Its
   configuration is versioned in `deploy/` and checked in CI. The project never changes the
   production server's sites or certificates.
2. **The project stack**, built lab by lab from the secops-demo instructions: OpenSearch,
   Dashboards and an nginx TLS front door (Lab 3), a supply-chain-hardened pipeline (Lab 4),
   detection as code on Suricata telemetry (Lab 5) and threat-intelligence enrichment
   (Lab 6). It runs on my laptop with Docker (WSL2), never on the VPS. The telemetry in
   Lab 5 is synthetic Suricata EVE data, generated by scripts in this repository.

Risks and controls: [`RISK-REGISTER.md`](../RISK-REGISTER.md). Evidence: [`docs/evidence/`](evidence/).

## Lab 3: infrastructure as code (R-02, R-05)

| Requirement | Where |
|-------------|-------|
| Images pinned by digest, ports from `.env` | `compose.yaml`, `.env.example` |
| Admin password only as SOPS ciphertext | `.sops.yaml`, `secrets/opensearch.enc.yaml`, `scripts/init-secrets.sh` |
| Decrypt at deploy time, delete on teardown | `Makefile` (`secrets`, `up`, `down`) |
| Repeatable deploy | `make down && make up` twice, outputs in `docs/evidence/lab3/` |
| Lab PKI in front of Dashboards | `step-ca`, `make cert`, `nginx/frontdoor.conf`, `make chain` |

Choices beyond the lab text: every host port is bound to 127.0.0.1; the front door hides
its version and allows TLS 1.2+ only; the base image is nginx 1.30.7-alpine-slim, because
Trivy found 70 HIGH or CRITICAL issues in 1.27-alpine and none in 1.30.7-alpine-slim.

## Lab 4: CI/CD and supply chain (R-01, R-08, R-09)

### What each job blocks

| Job | What it blocks | Risk |
|-----|----------------|------|
| `lint` / ShellCheck, Hadolint | Broken scripts and unsafe Dockerfile patterns | Build integrity |
| `lint` / Semgrep | Known insecure code patterns | Application flaws |
| `workflow lint (zizmor)` | Unpinned actions, leaked credentials, risky triggers, a missing Dependabot cooldown | R-08, R-09 |
| `test` | Floating images, unpinned actions or packages, missing SRI, inline script on the main page | R-08, R-10, R-11 |
| `scan` / Trivy | An image with HIGH or CRITICAL vulnerabilities | R-14 |
| `secret scan (gitleaks, full history)` | A key or password anywhere in history | R-02 |
| `nginx config test` | A production nginx config that would not load | R-05, R-11 |
| `release` / Syft, Cosign | Unsigned or undocumented images reaching users; a release from a commit that is not on `main` | R-14, R-01 |

### Deliberate choices

- `persist-credentials: false` on every checkout, so no later step can read the token
  from `.git/config`.
- Trivy runs from its image pinned by digest, not through `trivy-action`. In March 2026
  attackers moved 76 of 77 `trivy-action` tags to an infostealer and published malicious
  Trivy 0.69.4 to 0.69.6. Pinning the action to a SHA was not enough on its own, because
  the action downloads Trivy at run time.
- For the same reason the ShellCheck action gets an explicit `version`, and Syft and
  Cosign get explicit versions: every tool fetched at run time is pinned too.
- Semgrep and zizmor are installed from `requirements-lint.txt` at exact versions, so
  Dependabot can update them through the same 7-day cooldown.
- The release job signs the image digest, not the tag, and refuses a tag that points at
  a commit outside `main`.
- `${{ ... }}` never appears inside `run:` scripts; values reach the shell through `env:`.

### Branch protection

The repository is public on GitHub Free, so rulesets are enforced. `main` requires a pull
request and the checks `secret scan (gitleaks, full history)`, `site checks (SRI)`,
`nginx config test`, `workflow lint (zizmor)`, `lint`, `test` and `scan`. The exported
ruleset is in `docs/ruleset-main.json`. I never merge a red pull request; the governance
workflow proves that every commit on `main` arrived through a merged pull request.

### Signing decision

Images are signed keyless with Sigstore: the workflow's OIDC identity gets a short-lived
certificate from Fulcio, and the signature is recorded in the public Rekor log. The
repository is public, so the log entry discloses nothing that is not already public. No
long-lived signing key exists to steal.

### Proof that the gates close

Two pull requests were opened only to fail, then closed without merging:
`demo/vulnerable-base` (Trivy fails `scan`) and `demo/unpinned-action` (GitHub refuses the
run; zizmor and `test` fail too). Screenshots in `docs/evidence/lab4/`.
